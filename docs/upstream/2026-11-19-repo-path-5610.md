I measured the options on real builds of current `v2/main` (`640a8c3`, mcp-server-git 2026.11.18, which includes
#5626): one copy per option, patched only as listed, with the same confinement checks in all of them.
`qwen3:4b-instruct`, 5 read-only git tasks × 3 repeats, answers checked in code. The agent is **not** told the
repository path; only the server knows it. The client puts the server's `instructions` into the system prompt.

| Option | Passed | `repo_path` errors | Median time |
|---|---|---|---|
| today: `repo_path` required, undescribed on 12/14 tools, no instructions | 9/15 | 14 of 33 calls | 35s |
| `repo_path` description on every tool names the allowed repository | 12/15 | 0 of 14 | 24s |
| server `instructions` name the allowed repository | **15/15** | 0 of 17 | 22s |
| `repo_path` optional on every tool, defaulting to `--repository` (through `open_repo`) | **15/15** | 4 of 23 | 9s |

What the traces show:
- **Today:** the model guesses `"."` or a name like `"project"`, and all 14 errors are "outside the allowed
  repository". Three runs stopped there and asked the user for the path.
- **Described:** no path errors at all. All 3 failures are one task refused before any tool call ("I don't have
  access to project history"), which is unrelated to `repo_path`.
- **Instructions:** the model has the exact path before its first call, so there are no errors and the fewest calls.
- **Optional:** the model still sent `repo_path` on 20 of 23 calls, usually `"."`. It recovered every time,
  because the error names the allowed repository, and the calls without it just worked. This was the fastest by far.

Today vs instructions or optional (9/15 vs 15/15) is significant even at this size (Fisher's exact p ≈ 0.02).
The differences between the three options are not (described vs the others p ≈ 0.22).

My read: as suggested above, the two complement each other. Instructions are the smallest change (no
schema change) and removed every path error, but they only help when the client passes them to the model.
Optional `repo_path` works whatever the client does, and the existing "outside the allowed repository" error
already lets a model recover from a wrong guess. Both together look safest, but I didn't measure the
combination. One small model and a small sample, so treat this as direction, not proof.
